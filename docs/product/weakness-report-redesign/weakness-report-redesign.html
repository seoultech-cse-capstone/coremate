개념마다 세 줄

무엇이 약한지 → 왜 틀렸는지 → 어떻게 복습할지. 카드를 펼치지 않아도 이 세 줄로 끝나요.

기호 대신 문장

내 답과 정답을 선택지 문장으로, 그 답을 고른 이유를 한 줄로 보여요. AI 문장의 말투는 앱과 같은 해요체로 맞춰요.

자료는 접고, 끝은 행동

학습 자료와 틀린 문제는 펼칠 때만 보여요. 카드마다 바로 풀 수 있는 버튼이 있어요.

의사코드는 알고리즘을 특정 프로그래밍 언어에 얽매이지 않고 단계적으로 표현하는 비형식적 기술 방식이다.

헷갈리는 짝
vs 실제 구현 코드

실제 구현 코드는 특정 언어 문법에 맞아 실행을 목표로 하지만, 의사코드는 언어 독립적으로 알고리즘의 논리를 설명하는 데 목적이 있다.

vs 알고리즘

알고리즘은 문제 해결 절차 그 자체이고, 의사코드는 그 절차를 사람이 이해하기 쉽게 표현한 방식이다.

꼭 짚을 포인트
  • 실행 가능한 코드가 아니라 알고리즘의 논리와 흐름을 설명하는 표현이다.
  • 엄격한 표준 문법보다 단계의 순서와 핵심 동작의 명확성이 중요하다.
  • 구현 세부사항은 설명 목적에 맞게 단순화할 수 있다.
예시·오개념 노트·기초 복습까지 전체 자료
이 개념 문제집 풀기 · 7문제
D유형이 엇갈린 카드 · 자료 펼침

모르는 건 조용히, 순서는 관계로

  • 1단계백엔드 판정과 AI 판정이 갈린 개념은 유형 칩을 빼고 이유만 한 줄로 알려요. “판정 보류” 같은 내부 말은 쓰지 않아요.
  • 3단계“먼저 볼 개념”은 관계 테이블의 선수 관계예요. 선수 개념이 이미 약점이면 표시하고, 누르면 그 카드로 이동해요.
  • 1단계개념 한눈에 보기는 핵심 한 줄 → 헷갈리는 짝 → 꼭 짚을 포인트 세 개만. 예시·오개념 노트·기초 복습은 전체 자료로 넘겨요.
  • 3단계AI 문장의 해요체는 프롬프트 규칙으로 맞춰요. 학습 자료·문제는 교재 문장이라 원문 그대로 둬요.

목업 속 숫자·개념·문장은 로컬 DB 분석표 #18과 문항·진단 프로필·개념 관계 테이블에서 가져왔어요. 소요 시간 28초는 테스트 계정 풀이 기록이라 모든 문항이 같아요.

결정 필요

팀이 정할 것

  1. 약점 점수를 화면에서 완전히 뺄까요?

    제안: 숫자는 빼고 순위만 남겨요. 60점과 57점의 차이는 사용자에게 뜻이 없고, 정렬 순서로 충분해요.

  2. 유형 이름 네 가지를 사용자 문구로 정해야 해요

    제안: 개념 혼동 · 적용 부족 · 속도 부족 · 풀이 실수. 지금은 “속도·숙련 부족”, “풀이 실행 오류”로 나가요.

  3. “틀린 문제만 다시 풀기”를 새로 만들까요?

    지금 앱에는 풀이 기록 보기와 개념 문제집(개념당 7문제)만 있어요. 만들면 카드 버튼을 두 개로 나눌 수 있지만 새 풀이 모드라 백엔드 작업이 따로 들어요.

  4. 화면 요구사항 SCR-WEAK-05를 새 구조에 맞춰 고칠까요?

    완료 기준(약한 개념·도출 이유·근거 기록·친절한 개념 설명·복습 방향)은 오히려 더 잘 채워져요. 표시 정보 목록만 새 이름으로 바꾸면 돼요.
