# 백엔드 읽기 API 부하테스트 리포트

- 관련 이슈: #273
- 대상: 일반 읽기 API 5종 (출석 캘린더 · 콘텐츠 과목 · 알림 미읽음수 · 진행률 요약/과목)
- 도구: k6 (`apps/backend/loadtest/`)
- 환경: **로컬 단일 머신** Docker Compose (backend + MySQL 8 + Redis 7.2), 10코어
- 방식: `ramping-vus`, 4분간 VU 단계적 상승
- 주의: k6·백엔드·MySQL이 **같은 10코어 머신을 공유** → 서버와 부하 생성기가 CPU를 두고 경쟁한다.
  따라서 아래 수치는 실제 분리 배포 환경보다 **보수적(낮게)** 나온 값이다.

## 결과 요약

| 시나리오 | think time | 최고 VU | 처리량(RPS) | p95 | p99 | max | 에러율 |
|----------|-----------|--------|------------|-----|-----|-----|--------|
| A. 현실적 부하 | 1~3초 | 300 | 273 | 3.97ms | 6.28ms | 73ms | 0% |
| B. 최대 부하 | 0초 | 400 | **3,235** | 147ms | 211ms | 502ms | **0%** |

- **시나리오 A** = 실제 사용자처럼 화면 사이 텀을 둔 부하. 동시 300명이 붙어도 서버는 **거의 무부하**(p95 4ms, CPU 피크 ~73% = 1코어 미만). 즉 현실적인 동접 300명은 여유롭게 처리한다.
- **시나리오 B** = 텀 없이 계속 두드려 서버 순수 한계를 탐색. **초당 3,235건**을 처리하면서도 에러 0%, p95 147ms로 목표(800ms) 안쪽. 지연이 4ms→147ms로 오르며 무릎 지점이 **보이기 시작**했지만, 임계선을 넘겨 무너지진 않았다.

## 병목 분석

시나리오 B 피크에서 `docker stats` 관측:

| 자원 | 피크 사용량 | 판정 |
|------|-----------|------|
| backend CPU | **~360% (≈3.6코어)** | 주 병목 |
| MySQL CPU | **~330% (≈3.3코어)** | 주 병목 |
| backend 메모리 | 778MB (제한 대비 여유) | 여유 |
| MySQL 메모리 | 418MB | 여유 |

- **병목은 CPU다.** backend(~3.6코어) + MySQL(~3.3코어) + k6가 10코어를 거의 다 소진했다.
- **HikariCP 커넥션 풀(기본 10)은 이번 읽기 부하에서 병목이 아니었다.** 풀이 부족했다면 요청이 커넥션을
  기다리며 지연이 폭증했을 텐데, p95가 147ms로 낮게 유지됐다. MySQL이 요청을 제때 소화했다는 뜻.
  → 이슈 #273의 "1순위 병목 = 풀 크기 10" 가설은 **읽기 부하에 한해 반증**됨. (쓰기·트랜잭션 부하는 별도 검증 필요)

## 결론

- **현실적 트래픽 기준 동접 300명은 여유롭게 버틴다** (p95 4ms, CPU 1코어 미만).
- 서버를 텀 없이 몰아붙여도 **초당 3천 건 이상을 에러 없이** 처리했고, 그 지점의 병목은
  **DB 커넥션 풀이 아니라 CPU**였다.
- 로컬 단일 머신·부하 생성기 경쟁이라는 제약이 있어, 실제 배포 환경의 한계는 이보다 높을 것이다.

## 재현 방법

```bash
# 현실적 부하 (시나리오 A)
docker run --rm --network host -v "$PWD/apps/backend/loadtest:/lt" \
  -e LOADTEST_USERS='[{"email":"loadtest1@coremate.test","password":"..."}]' \
  grafana/k6 run /lt/read-stress.js

# 최대 부하 / 한계 탐색 (시나리오 B)
docker run --rm --network host -v "$PWD/apps/backend/loadtest:/lt" \
  -e THINK_TIME=0 -e STAGE_PEAK=400 \
  -e LOADTEST_USERS='[...]' \
  grafana/k6 run /lt/read-stress.js
```
